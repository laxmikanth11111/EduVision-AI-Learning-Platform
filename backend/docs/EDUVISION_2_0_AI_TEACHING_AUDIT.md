## 1. AI Mastery Tutor Forensic Analysis

### 1.1 Current Implementation Tracing
- **Primary Service:** `backend/app/services/mastery_tutor_service.py` (997 lines).
- **API Endpoints (`backend/app/api/v1/tutor.py`):**
  - `POST /api/v1/tutor/sessions`: Creates learner-scoped session.
  - `POST /api/v1/tutor/sessions/{session_id}/messages`: Appends user message and produces assistant reply.
  - `GET /api/v1/tutor/conversations/{conversation_id}/messages`: Retrieves message history (see Breakage 1 in Architecture Audit).
  - `POST /api/v1/tutor/remediate`: Generates targeted remediation for a weak concept.

### 1.2 Root Cause of the Generic Tutor Responses
In `mastery_tutor_service.py`:
```python
rag_chunks = context.get("rag_chunks") or []
if not rag_chunks:
    # RAG is cold: only a deterministic answer can be grounded.
    return (
        baseline,
        TutorSourceKind.DETERMINISTIC.value,
        context.get("attribution"),
        baseline_conf,
        None,
        None,
        {"deterministic_reason": "no_retrieval_context"},
    )
```
And `baseline` is generated by:
```python
def _deterministic_explanation(self, ..., context: dict[str, Any]) -> str:
    name = concept_name or (context.get("weak_concept_name") or "this concept")
    mastery_txt = f"{mastery:.0f}%" if mastery is not None else "not yet measured"

    lines = [
        f"Here's a focused summary on **{name}**.",
        f"Your current mastery is **{mastery_txt}**.",
    ]
    ...
    if not context.get("rag_chunks"):
        lines.append(
            "There is no rich source material in your library matched to "
            "this question yet, so this answer is generated from your mastery "
            "data rather than a document."
        )
    return "\n\n".join(lines)
```

### 1.3 Key Failures Identified
1. **Exposure of Internal System Limitations:** Directly states *"Your current mastery is not yet measured"* and *"There is no rich source material in your library matched to this question yet"*.
2. **Binary RAG Dependency:** If vector indexing is pending, disabled, or returns low similarity, the tutor completely refuses to answer educational questions, even when the concept is well-known (e.g. *"What is a CPU?"* or *"Explain ATP synthase"*).
3. **Absence of Socratic Pedagogical Strategies:** The tutor does not explain through analogies, step-by-step breakdowns, real-world examples, or follow-up questions.

### 1.4 Architecture for AI Tutor 2.0 (The Three Answer Modes)

The tutor must implement three explicit, intelligent operational modes:

| Mode | Condition | Pedagogical Behavior | Citation / Attribution |
|---|---|---|---|
| **Mode 1: Source-Grounded** | Concept is directly covered in the student's uploaded PPTX/PDF | Explains accurately from the source material, citing specific slides and sections. | `"Based on Slide 4 of your presentation..."` |
| **Mode 2: Source + Enrichment** | Concept is mentioned in the document, but lacks depth or context | Explains the source definition first, then enriches with intuitive analogies, real-world examples, and deeper technical details. | `"Your notes introduce this on Slide 2; to make it concrete, consider this analogy..."` |
| **Mode 3: Outside Source** | Student asks a question not in their uploaded document | Never fails. Acknowledges connection gracefully and explains clearly using comprehensive AI domain knowledge. | `"That isn't covered directly in your uploaded material, but it connects to your topic. Let me explain it..."` |

## 2. Automated Visual & Animation Generation Audit

### 2.1 Visual Generation Analysis
- **Existing Services:**
  - `backend/app/services/visualization_decision_service.py`: Contains a 22-category rule matrix (`CATEGORY_VISUALIZATION_MATRIX`) mapping educational topics (Algorithms, Architectures, Workflows, Biology cycles, etc.) to visualization types (Flowchart, Timeline, Block Diagram, Mind Map, etc.).
  - `backend/app/services/visual_persistence_service.py`: Stores SVG and Mermaid visual canvases.
- **Root Cause of Underperformance:**
  1. These services are completely detached from the document ingestion workflow. When a user uploads a document, visuals are NOT generated automatically.
  2. In `player.html`, visual generation is triggered only if the user manually clicks "Generate Visual" on slide `2*i + 1`.
  3. In `player.html`, client-side regex heuristics (`recommendVisualType`) are used instead of querying the backend's rich classification engine.

### 2.2 Animation Engine 2.0 Analysis
- **Existing Services:** `animation_planner_service.py`, `animation_classification_service.py`, `animation_validation_service.py`.
- **Flaw:**
  - The current animation runtime in `player.html` renders basic SVG translation transitions (`.anim-scene-card`, keyframe opacity/transform).
  - It lacks true educational process sequencing (e.g. for TCP 3-way handshake: Client SYN &rarr; Server SYN+ACK &rarr; Client ACK &rarr; Connected state explanation).
- **Target for Animation Engine 2.0:**
  - Educational storyboards divided into discrete semantic scenes.
  - Step-by-step visual transitions synchronized with audio transcripts or explanatory subtitles.
  - Interactive playback controls (Step forward, Step backward, Speed toggle, Scrub timeline).

## 3. Video Teaching Engine 2.0 Audit

### 3.1 Existing Services
- `backend/app/services/video_project_builder.py`: Decomposes topic into `VisualLearningModel`.
- `backend/app/services/video_project_service.py`: Creates persistent `video_projects` rows.
- `backend/app/services/video_renderer_service.py`: Compiles Remotion/FFmpeg scene compositions.

### 3.2 Required Enhancements for Educational Efficacy (Section 12)
Videos must not merely be a slideshow of AI images with TTS narration. They must follow an educational teaching structure:
1. **The Hook:** An engaging opening question or relatable dilemma.
2. **Intuitive Definition:** Plain-English explanation without jargon overload.
3. **The 'Why':** Why this concept was invented or why it matters in the real world.
4. **Visual Walkthrough:** Step-by-step breakdown of the mechanism or architecture.
5. **Real-World Analogy:** (e.g. Restaurant waiter for API, Post office for Packet routing).
6. **Common Misconceptions:** What students typically get wrong on exams.
7. **Quick Knowledge Check:** 1 interactive review question before concluding.

## 4. Content Quality Control & Validation Pipeline (Section 24)

AI-generated content must undergo rigorous validation before presentation to students:
- **Source Alignment Scoring:** Verified via embedding cosine similarity or semantic overlap against extracted `content_blocks`.
- **Factual Integrity:** Prohibits fabricated citations or claims that external knowledge was present in the student's file.
- **Readability & Difficulty Calibration:** Adjusts vocabulary based on target learner difficulty level.
- **Visual & Diagram Correctness:** Validates Mermaid and SVG syntax prior to rendering, preventing broken graphic artifacts.
